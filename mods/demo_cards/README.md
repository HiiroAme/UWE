# 第二个演示 Mod：卡牌

这个 Mod 存在的意义是**当第二份证据**：它和 `demo_hex` 用了完全不同的玩法与完全不同的
State 形状，而引擎**一行都没改**。

```
                demo_hex（六边形遭遇战）      demo_cards（卡牌）
State 形状      节点 / 相邻表 / 单位          牌堆 / 手牌 / 弃牌堆（列表）
空间概念        有（六边形坐标、相邻）         没有（场外变化，D-01）
核心循环        移动 / 攻击 / 结束回合         抽牌 / 出牌 / 结束回合
随机            伤害 1~3                      洗牌（Fisher–Yates）
派生值          战斗力、优势                   手牌数、牌堆数
界面            格子 + 战报 + 按钮             卡片排 + 战报 + 按钮
```

## 目录

```
demo_cards/
├── mod_info.json     元信息（含 uses / params、初始化钩子与默认页面）
├── data/             注册表条目
│   ├── 05_phases.json     主阶段允许的动作
│   ├── 07_entities.json   三张牌的模板（打击 / 格挡 / 闪电）
│   ├── 09_system.json     全局参数初值（回合、能量、分数……）
│   ├── 20_formulas.json   派生值（手牌数 / 牌堆数）
│   ├── 30_rules.json      规则（手牌没满、牌在手上、能量够）
│   ├── 40_actions.json    动作（抽牌 / 出牌 / 结束回合 / 洗牌 / 重算派生值）
│   ├── 50_commands.json   命令（分支 → 动作）
│   ├── 60_triggers.json   触发（牌堆空了 → 洗牌；抽牌 / 出牌后 → 重算派生值）
│   ├── 65_events.json     事件定义
│   ├── 70_inputs.json     输入映射
│   └── 80_ui.json         牌桌页面
└── scripts/
    ├── init.py            初始化：模板 → 卡牌表、摆好牌堆与手牌
    └── ui_table.py        牌桌界面：手牌是可点击的卡片
```

玩法实现不在这个文件夹里：抽牌 / 出牌 / 洗牌 / 结束回合来自模块
`pack_cards_basic`（服务），追一行战报用模块 `pack_common` 的通用工具服务。
`mod_info.json` 里的 `uses` 声明用到谁、`params` 说明"哪条路径是牌堆 / 手牌 / 弃牌堆"。

## 玩法

- 开局：手牌 3 张、牌堆 5 张、每回合 3 点能量；
- **抽牌**：牌堆顶进手牌（手牌上限 5）；牌堆被抽空时自动触发**洗牌**（弃牌堆洗回牌堆）；
- **出牌**：点手牌即可（能量够才可点），扣能量、加分、牌进弃牌堆；
- **结束回合**：回合 +1、能量回满；
- 派生值 `hand_size` / `deck_size` 由触发链在抽牌 / 出牌后重算，存读时也会自愈。
