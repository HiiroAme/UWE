整体思路介绍：
整个引擎分为引擎核心、模块、mod三部分，引擎向模块提供接口，模块主要是可执行的函数和代码文件，编写难度较高（这被认为是必须的，因为引擎不可能去一个一个细节编写每种不同的函数，比如不同的攻击方式，因此只能通过外部注入，但是引擎可以提供便捷直观的接口），mod主要是json文件，目前的演示mod里面有一些薄胶水和编排的脚本，但是总体编写难度低，且以后会直接通过可视化编辑器编辑（包括地图，单位等等内容）
一个模块可以给多个mod使用，比如他提供不同的攻击方式（crt，血量...）于是mod便可以直接引用模块里面的函数。
不建议在正式版之前编写模块和mod的原因就是正式版预计会出可视化编辑器，它和这二者都有关系，因此接口和格式可能会有调整，正式版之前的模块可能就因此不再适用。

**版本 0.0.0（demo）· 可行性验证版**

一个把"玩法"和"引擎"分开的兵棋引擎。引擎本身不接触任何玩法名词——没有"单位"、
没有"攻击"、没有"六边形"、没有"回合"；它只提供机制：状态、命令、变化量、规则、事件、
存档与视图接口。玩法实现放在**逻辑模块**里，一局游戏的地图、兵力、数值与排版放在 **Mod** 里。

> 引擎给机制，模块给实现，Mod 给配置与事实。

这一版的目标不是"做一个完整的游戏"，而是验证这条路真的走得通：
**引擎里没有一行玩法逻辑，照样能跑起三种完全不同的玩法。**

## 这个 demo 想证明什么

1. **引擎不含玩法**：引擎源码里没有一处认识"六边形 / 攻击 / 卡牌"这些概念
   （"六边形"只在注释里作为"多边形"的举例出现）；
2. **模块可以复用**：同一个 CRT 战斗模块，换个 Mod 换个参数就能再用；
   六边形几何、寻路、卡牌流程同理；
3. **Mod 可以只写数据**：白鹭河遭遇战有 729 格（27×27 正方形）地图、渡口、控制区、混乱、战后挺进，
   而它的玩法实现全部来自模块，Mod 自己只写"这一局的事实"和界面排版；
4. **自动结算跑得通**：查表、逐场结算、撤退、混乱恢复、胜负判定都由引擎与模块完成，
   玩家只负责声明打哪一场。

## 快速开始

要求：Python 3.10 及以上（开发与测试环境为 3.12）；桌面系统：**Windows**
（这次 demo 只准备先在 Windows 上运行）。

```bash
pip install -r requirements.txt   # 只有一个第三方依赖：pygame
python main.py
```

启动后：`开始新游戏` → 选一个 Mod。**建议先玩「白鹭河遭遇战」**（这张地图比较完善，
另外两个是测试用的，但都保留着）；
想了解"一个 Mod 长什么样"，从「六边形演示」看起。

## 内置的三个演示

| Mod | 是什么 | 建议 |
|-----|--------|------|
| **白鹭河遭遇战**（`demo_river`） | 进阶示例：729 格（27×27 正方形）六边形地图、三处渡口、CRT 战斗结果表、控制区、混乱、战后挺进、12 回合攻守胜负 | 先玩这个，一局能看到引擎的全部能力 |
| **六边形演示**（`demo_hex`） | 最小闭环：7 格地图、两个单位、移动、攻击、随机、存档、回放 | 想学怎么写 Mod，从它读起 |
| **卡牌演示**（`demo_cards`） | 完全换一套玩法：牌堆 / 手牌 / 弃牌堆、抽牌、出牌、洗牌 | 看"同一套引擎机制如何表达另一种玩法" |

## 怎么玩（以白鹭河为例）

鼠标：

- **左键点击**：选中、预览、确认（点无关位置取消选中）；
- **移动阶段**：点自己的单位选中 → 点可到达的格子预览路径 → 再点同一格确认移动；
  同一个格子里有多个单位时，反复点它会轮流选中；
- **攻击阶段**：先点己方单位加入参战名单，再点相邻敌军声明一场；可以声明多场，
  然后按右下角「开始结算（N 场）」，逐场点「下一场」结算——每场打完可以选择是否战后挺进；
- **右下角按钮的文字会跟着流程变**：`进入攻击阶段` → `开始结算` → `下一场` → `结束回合（交给对方）`；
- **滚轮**：以屏幕中心缩放地图；**按住拖动**：平移地图。

键盘：

- `Esc`：打开 / 关闭游戏内菜单（存档、返回首页、规则）；首页按 `Esc` 退出程序；
- `S`：存档；`F5`：重新加载当前 Mod（改了 Mod 数据后不用重启，开发时用）。

开局会弹一次背景与规则说明；游戏中随时可以从菜单里的「规则」回顾。

## 引擎长什么样

```
main.py                 启动入口：只有它负责"选平台"（窗口 / 文件 / 脚本加载）
engine/src/
  core/                 纯逻辑：状态树、变化量、命令管线、规则、事件、注册表、存档格式
                        （不 import pygame、不碰文件系统，有架构守卫测试盯着）
  adapters/             唯一接触平台的层：pygame 窗口与渲染、本地文件、Python 脚本加载
  modload/              模块与 Mod 的加载、校验、依赖解析与绑定
  shell/                外壳界面：首页 / 设置 / 关于 / 选 Mod / 读档 / 游戏内菜单
                        以及外置的文字与图标资源（shell/assets/）
modules/                逻辑模块（8 个），见下表
mods/                   示例 Mod（3 个）
tools/package_source.py 源码发布包打包器（开发工具，不会被打进发布包）
tests/                  自动测试（不进发布包）
saves/ logs/            存档与运行日志（运行时生成）
```

几条一直守着的原则：

- **只有适配器连接前后端**：`core` 只认接口（端口），窗口、文件、脚本加载都在 `adapters` 里；
- **状态变化走同一条管线**：命令 → 规则校验 → 动作与服务 → 变化量 → 状态；
  每一步都有溯源日志，存档 = 快照 + 变化量叠加，回放不重跑规则；
- **随机可复现**：随机数走统一服务，种子状态进存档；
- **引擎不带内容**：连"保存 / 退出"这类系统事件的登记也在模块 `pack_common` 里，
  引擎源码树中没有任何内置内容目录。

## 模块与 Mod 的分工

- **模块**：可复用的实现。同一能力可以有多种做法供挑选，Mod 在 `mod_info.json` 的
  `uses` 里声明用哪些模块，用 `bindings` 选具体实现，用 `params` 给这一局的参数；
- **Mod**：一局游戏的事实与排版。`data/` 里是注册表条目（地形、实体、规则、动作、
  命令、输入、界面……），`scripts/` 只放这一局独有的编排与画法，`assets/` 放资源。

标识约定：每个模块与 Mod 都有"唯一 id / 文件夹名 / 称呼名"三件套——id 管命名空间
（永不改名），文件夹名只管从哪读，称呼名给人看、随便改。版本号现阶段统一 `0.0.0`。

### 现有模块

| 模块 | 提供 |
|------|------|
| `pack_common` | 通用内核内容：系统事件登记、通用工具服务（每个 Mod 自动带上） |
| `pack_hex_grid` | 六边形几何：键、相邻、距离、坐标换算、字符地图解析、网格画法 |
| `pack_path_hex` | 六边形移动：可达范围（按地形消耗）、路径还原、控制区（ZOC） |
| `pack_combat_basic` | 基础战斗：定值 / 骰子伤害与通用攻击骨架 |
| `pack_combat_crt` | 战斗结果表：攻防比 → 1d6 → 结果码 → 效果（消灭 / 撤退） |
| `pack_wargame_core` | 兵棋基础动作：移动落点、行动力、回合推进 |
| `pack_cards_basic` | 基础卡牌：抽牌、出牌、洗牌、弃牌堆 |
| `pack_camera` | 界面相机：滚轮缩放 + 拖动平移（界面状态，不进存档） |

## 开发

```bash
python run_tests.py                                        # 自动测试（当前 703 条，全绿）
python -m compileall -q engine/src mods modules main.py    # 语法检查
python tools/package_source.py                             # 打源码发布包
```

打包走白名单：只复制 `main.py`、`engine/src`、`modules`、`mods`、`README.md`、
`requirements.txt`、`UWE.spec`，其余（设计文档、测试、存档、日志）一律不进包。
产物在 `dist/UWE-<版本>-demo-src/` 与同名 zip；`--dry-run` 可以只看清单不写盘。

要打 Windows 的 one-folder exe（双击即玩，需要先 `pip install pyinstaller`）：

```bash
python -m PyInstaller --noconfirm UWE.spec
```

产物在 `dist/UWE-<版本>-demo-win64/`：`UWE.exe` + `_internal/`（引擎与 pygame）+
旁边的 `mods/`、`modules/` 和 README。它是**绿色便携版**：整个文件夹一起拷走，
存档与日志就在文件夹里；别放进 `Program Files` 这类不可写目录。

## 当前状态与已知限制

- 版本号 0.0.0 表示**格式未定型**：模块、Mod 与存档结构都还可能变；
- **可视化编辑器还没有**：现在写 Mod 靠手写 JSON，必要时加少量 Python；
- 只有桌面端（pygame）；exe 包已经能双击玩，源码运行则需要自己装 Python；
- 音频接口已经接通（宿主会注入 `PygameMedia`，相对路径按 Mod 目录解析）；示例里还没有实际用到；
- 目前只在 Windows + CPython 3.12 上完整跑过测试。
